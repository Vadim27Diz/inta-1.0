## Найденные причины (корень, не симптом)

- **Новый фрейм в Figma по умолчанию `clipsContent: true`.** `row()`/`sectionFrame()` в
  `figma-playground.js` создавали фреймы голым `figma.createFrame()` без явного сброса; ряд
  auto-layout хугается ровно по высоте контента (36px у кнопки) — на 4px короче кольца фокуса
  (оно на 2px больше поля с каждой стороны, итого 40px) → верх/низ кольца обрезан. Задело
  primary в ряду состояний, `outline`/`ghost`/`link` и `Textarea` на карточке `surface-raised`.
  Фикс — единая точка создания фрейма (`newFrame()`), а не ручная расстановка `clipsContent = false`
  по каждому месту (там, где её хоть раз забыли, баг и возник).
- **У Kbd ширина `FIXED` 20, а текст — без component property.** `primaryAxisSizingMode: "FIXED"`
  на мастер-компоненте держал ширину ровно 20px независимо от содержимого — `«K+⌘»` вылезал за
  рамку. Отдельно текстовый слой никогда не был подключён как TEXT property (создавался напрямую
  через `.characters =`, без `addComponentProperty`), поэтому его не ловила проверка «текст меняется
  при использовании — должен быть property» (как и у Badge: 9 вариантов несли литеральный текст,
  совпадающий с именем варианта, тоже без property). Код (`kbd.tsx`) был верным с самого начала
  (`min-w-5`, `inline-flex`, без фиксированной ширины) — баг жил только в Figma-компоненте.
