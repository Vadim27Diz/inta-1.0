## Находки (ловушки, с механизмом)

1. **`component.clone()` ТЕРЯЕТ `componentPropertyReferences`** (привязки TEXT/BOOLEAN свойств к
   текстовым слоям — `characters`/`visible`) — не копирует их на клон. После клонирования
   компонента-варианта все `Text#.../Required#.../Hint#.../Error#...`-привязки на его текстовых слоях
   нужно восстанавливать вручную: `node.componentPropertyReferences = { characters: "Text#id" }`
   (свойство напрямую записываемое, читается через `node.componentPropertyReferences`). Поймано
   `figma:layout`-правилом «текст — через property» (`nakedText`). **Не записано в skill** — стоит
   занести в `figma-component-conventions` или `figma-use`-ловушки, не сделано в этой сессии.
2. **Если `use_figma`-скрипт бросает необработанное исключение — ВСЕ его мутации канвы откатываются**,
   включая то, что выполнилось до точки падения. Проверено дважды в этой сессии (оба раза: часть
   успешно выполненных fix'ов исчезала при следующем чтении). Разбивать на мелкие
   гарантированно-успешные шаги или собирать ошибки в массив вместо throw, если нужна частичная
   устойчивость.
3. **`ComponentSetNode.defaultVariant` — read-only**, «самый верхний-левый вариант пространственно»,
   нельзя присвоить явно (`set.defaultVariant = node` → `Error: read-only property`). См. «Факты»
   выше.
4. **Порядок `variantOptions` фиксируется по порядку ПЕРВОГО появления значения** (создание нового
   ребёнка ИЛИ переименование существующего — неважно). Чтобы получить `lg,md,sm`: создать
   `Size=lg,...` ПЕРВЫМ, переименовать существующие в `Size=md,...` ВТОРЫМ (тот же узел), создать
   `Size=sm,...` ПОСЛЕДНИМ. Порядок свойств в самом имени (`Size` перед `State`) складывается
   автоматически в ту же сторону. Подтверждено тестом на одноразовом наборе (`TEST_ORDER_1`,
   создан/проверен/удалён в этой сессии) и затем на реальных Label/Field.
5. **Визуальная позиция в сетке набора — ОТДЕЛЬНАЯ от `variantOptions` вещь**, определяется
   порядком `children` (COMPONENT_SET с `layoutMode: VERTICAL` стекует по индексу). Чтобы сетка шла
   `lg,md,sm` сверху вниз — `set.appendChild(node)` в этом порядке для каждого варианта (перемещает
   существующий узел в конец списка детей, не создаёт копию). Но сдвиг позиции в сетке = сдвиг
   defaultVariant (см. находку 3) — отсюда конфликт, который решил человек.
6. **`instance.swapComponent(newMain)`** меняет main component инстанса, сохраняя overrides где
   можно, включая `isExposedInstance` — так Field-клоны получили вложенные Label/Input нужного Size
   без потери переключаемости из панели Properties.

## Открытые решения пользователя

- **Перестановка порядка `Size` в Input, Native Select, Toggle, Toggle Group, Avatar, Icon** —
  по-прежнему вручную человеком в Figma UI (решение прошлой сессии: клонирование агентом отвергнуто
  из-за риска для инстансов). `figma:layout` теперь автоматически поймает рассинхрон у Input против
  Label/Field — сейчас это единственное нарушение в `npm run verify`, исчезнет само, когда человек
  переставит Input на `lg,md,sm`. Остальные наборы (Native Select и т.д.) пока не входят в проверку
  `sizeOrderConsistency` (у них Size пока не совпадает по значениям с Input/Label/Field — добавить
  их в `SIZE_ORDER_TARGETS`, когда у них появится паритет).
