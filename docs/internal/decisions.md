## 2026-10-25 — chore/pipeline-tooling слита в main напрямую, без PR

По прямой просьбе человека: `git merge --ff-only` в локальный `main` (сначала до `origin/main`,
потом до `chore/pipeline-tooling`) вместо обычного для этого репозитория пути через GitHub PR
(все прошлые мёржи #1–#18 — через PR). Слияние — чистый fast-forward без конфликтов и без
merge-коммита: ветка была построена на актуальном `origin/main`, включая PR #18. Ветка
`chore/pipeline-tooling` удалена после слияния (`git branch -D` — `git branch -d` отказался, т.к.
сравнивал с `origin/main`, где локальный `main` ещё не запушен; это ложная тревога, не причина
не удалять). Публикация на `origin` (прямой push или PR) — решение отдельное, не принято этим же
шагом, см. `state.md` → «Открытое» п.1.

## 2026-10-25 — Пакет D: D1 на Input (не Breadcrumb), D2 отложен

- **D1 механизм проверен на `Input`, не на `Breadcrumb`** — Breadcrumb назван в плане как пример,
  но его набора в Figma ещё нет (код есть, Figma в планах PR #17, см. `roadmap.md` п.6); живого
  «следующего нового компонента» в очереди не было вовсе. Решено человеком: построить механизм на
  одном уже перенесённом компоненте, чтобы не блокироваться на отсутствии кандидата. Спек
  `specs/input.json` снят задним числом, `figma-code-diff.mjs` берёт из него ожидания для секций
  «Input»/«Input states»; оставшиеся ~19 компонентов диффа остаются на хардкоде `EXPECT` до своей
  очереди.
- **Два реальных бага найдены и исправлены в `figma-spec-export.js` по ходу** (не гипотетические —
  всплыли на первом же живом прогоне): (1) паддинг читался с корня варианта, а не с прямого
  родителя текста — у составных полей (Input: корень = рамка с паддингом 0, паддинг реально на
  внутреннем фрейме "field") это давало `[0,0,0,0]` вместо настоящих отступов; (2) имена текстовых
  стилей резолвились только по первому варианту — у Input `Size=lg` использует другой текстовый
  стиль (`body/md`), чем `sm`/`md` (`body/sm`), и тихо терялся как `typo: null`. Оба фикса —
  структурные (читать с прямого родителя текста; собирать id стилей по всем вариантам), не
  специфичные для Input — применятся к любому следующему компоненту без доработки.
- **D2 не начат** — план требует «только если A2+C2 не хватит», а C2 (дельта-экспорт) ещё не
  прогонялся на живом Figma-сеансе ни разу, так что условие непроверяемо. Решено человеком:
  оставить как в плане, не строить плагин заранее.

## 2026-10-24 — Button: strokesIncludedInLayout и паддинги по Type×Size

- `strokesIncludedInLayout=false` на всех **30** вариантах `Variant=outline` с реальной обводкой
  (15 `Type=Button` + 15 `Type=Icon Button`), не только на 15 с видимым багом.
- Паддинги: Button sm/lg вертикаль `0→8` (`spacing/2`, id `5:110`), Button md не трогать (уже 8).
  Icon Button icon-sm все стороны `0→8` (`spacing/2`), icon/icon-lg все стороны `0→10`
  (`spacing/2-5`, id `5:111`). Горизонтальные паддинги Button (12/16/24) не менять.
- Код (`button.tsx`) не трогать — фикс только в Figma.
- Порядок записи, которым это сделано (эталон для похожих правок): проверка высоты текста живьём
  → снимок «до» → пилот по одному варианту на каждую из 6 пар `Type×Size` → сверка → 6 батчей
  (по группе за раз, сверка после каждого) → финальная сверка 0/300 → пересборка
  `figma/layout.json`.

## 2026-10-24 — Button: исключение из figma:code-diff для padY

`padY: 8` в проверке добавлен только для Button `md` (там `py-2` — литеральный CSS padding).
`sm`/`lg`/`icon*` намеренно его не получили: зазор там даёт Fixed-высота/квадрат + `items-center`,
не CSS padding — `getComputedStyle().paddingTop` читает `0px` независимо от Figma, проверка дала
бы ложное расхождение.
