# Пакет PR

Старый способ (каждая мелочь — свой PR и свой билд Chromatic) набрал ~55 билдов за проект;
отдельные билды в Chromatic удалить нельзя. Текущий способ — пакетами.

## Что входит в пакет

3–4 компонента или одно заметное изменение (как `chore/pipeline-tooling` — инструменты, не
компоненты). Состав растёт по мере переноса из очереди (`inta-port-queue`) — не нужно собирать
весь пакет заранее, он наполняется естественно.

## Мёрж — только после явных условий, все три

1. **ОК человека** на пакет целиком — не на отдельный компонент внутри него.
2. **`gh pr checks <N>` зелёные.** Писать «смёржен» только после подтверждения `gh` — пометка
   «PR смёржен» до этого подтверждения уже вызывала лишние вопросы на ревью.
3. **Снимок `figma/layout.json` переснят заново** (`inta-figma-snapshot`) и `npm run verify`
   прогнан после этого — снимок с начала работы над пакетом не считается.

## Chromatic — снимки принимаются один раз

Снимки новых историй принимаются человеком **один раз перед мёржем всего пакета**, не после
каждого компонента внутри него. TurboSnap (`onlyChanged`) снижает объём билда; `externals` для
токенов/глобальных стилей — правка токена пересобирает все снимки, это ожидаемо, не баг.
`skip` — только по заголовку/метке PR; пуши в `main` никогда не пропускаются, иначе теряются
базовые снимки для сравнения.

## Ветки

Одна ветка — один пакет. Если на двух открытых ветках оказались независимые `state.md` с разным
содержимым — это не конфликт, у каждой свой снимок состояния (`inta-handoff`); при мёрже порядок
веток решает человек.
