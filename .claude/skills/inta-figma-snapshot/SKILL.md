# Снимок раскладки `figma/layout.json`

Снимок — структурная сверка (секции, абсолютные слои, кольцо фокуса, порядок Size…), не
содержимое токенов. Два производителя, предпочитай первый.

## npm run figma:pull — REST, без Figma MCP в контексте

Снимает все 13 проверок локально через Figma REST API, без похода в контекст агента. Требует
`.env.local` (`FIGMA_TOKEN` со scope `file_content:read`, `FIGMA_FILE_KEY`) и
`figma/variable-ids.json` (карта id→имя переменной — REST отдаёт id, правило кольца фокуса
сравнивает по имени).

- `figma/variable-ids.json` устарел, если в Figma добавили/удалили переменную — пересними
  read-only через `use_figma` (один вызов `getLocalVariablesAsync()`, см. комментарий в начале
  `scripts/figma-layout-pull.mjs`).
- REST отдаёт **сохранённое** состояние файла — снимай после «версия сохранена», не во время
  правки.
- `npm run figma:probe` — пробник: сырой ответ в `figma/cache.local/` (игнорируется git), сверка
  какие поля реально приходят. Используй, если порт расходится с ожиданием — не гадай по памяти
  о формате REST, перепроверь на фикстуре.

## use_figma — fallback, когда нужна Plugin API (чтение «вживую», скрытые слои)

`.claude/skills/design-tokens/assets/figma-layout-export.js`, read-only, со
`skipInvisibleInstanceChildren=false` (иначе у скрытых слотов иконок пустой `children`).
Сохраняется **только** через `node scripts/figma-layout-save.mjs` — руками не копировать, он
проставляет `exporterHash`.

## Когда снимок считается устаревшим

Три независимые проверки, все обязательны (`npm run figma:layout` гонит их все):

1. **Хеш производителя.** `exporterHash` в снимке должен совпадать с хешем файла-производителя
   (`figma-layout-export.js` или `figma-layout-pull.mjs`, по `data.source`). Несовпадение —
   производитель менялся после снимка, пересними.
2. **Полнота ключей.** Снимок должен содержать ВСЕ ключи, которые объявляет `const data = {...}`
   в текущем производителе — даже при совпадающем хеше. Это ловит резейв старых данных задним
   числом (случилось реально — коммит `4ade50a`→`14d510c`, `exporterHash` совпал, а ключ
   `sizeConsistency` в данных отсутствовал).
3. **Относительно реальной Figma.** Это единственное, что не автоматизировать без похода в
   Figma — сверяется руками, переснимается перед каждым мёржем.

## Когда переснимать

- Перед каждым мёржем ветки в `main` — обязательно, не по желанию.
- После любой правки раскладки, компонента, его текстовых слоёв.
- После правки самого экспортёра/порта (ловушка 8 в `design-tokens/SKILL.md`: логика экспортёра
  — часть снимка).

## Красный снимок — не всегда чинить немедленно

Если `npm run figma:layout` падает по причине, не связанной с текущей задачей (например, другой
компонент в Figma ещё не закончен — см. `port-queue.md`, статус `figma-build`) — не
перегенерируй `figma/layout.json` молча новой базой на ветке, которая не про тот компонент. Это
сделает `verify` красным по причине вне рамок задачи. Зафиксируй находку, спроси человека.
