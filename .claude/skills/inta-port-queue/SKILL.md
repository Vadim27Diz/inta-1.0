# Очередь переноса Figma → код

Пайплайн этого проекта: **Figma первая, код — батчами по команде человека.** Компонент не
переносится в код сразу после утверждения в Figma — он ждёт в очереди. Полные правила файла — в
шапке `docs/internal/port-queue.md`, здесь — когда и как этим скиллом пользоваться.

## Завести запись

Новый компонент появляется в Figma (component set создан, даже как черновик) → строка в очереди
со статусом `figma-build` **в тот же день**, не потом. `npm run port:check` (в `verify`) поймает
несоответствие набора в Figma и отсутствующей строки — но лучше не доводить до красного.

## Снять спек — обязательно до конца Figma-сессии

Как только по компоненту получено «утверждаю» — спек снимается **прямо сейчас**, не «вернусь
позже»: формат и инструмент — `docs/internal/specs/README.md`. Статус переходит
`figma-approved` → `spec-captured` → `queued`. Пропустить этот шаг — значит на сессии переноса
придётся заново идти в Figma за числами, которые сжатие контекста уже стёрло.

## Порог батча — считает скрипт, не память агента

`npm run port:check` сам считает: **3 записи в `queued`** ИЛИ **40 КБ спеков**. Как только один
из порогов сработал (видно по строке `➜ ПОРА ПЕРЕНОСИТЬ` в выводе) — один раз сказать человеку,
без повторов в той же сессии:

> Накопилось N компонентов к переносу: **A, B, C** — спеки сняты, суммарно X КБ. Переносим?

- **Да** → переходи к `inta-component-cycle` (половина «перенос»), обычным батчем.
- **Нет** → в примечании строки очереди дописать `отложено <дата>: <причина>` (только `Edit`),
  статус остаётся `queued`. Не удалять запись, не откатывать статус. Порог снова сработает при
  следующем приросте — не повторяй вопрос раньше этого.

## Что никогда не делать с очередью

- Не начинать код по компоненту без строки в статусе `queued` и файла спека.
- Не удалять записи — ни перенесённые, ни отклонённые.
- Не править `port-queue.md` через `Write` — только `Edit` (как `handoff-archive.md`,
  `decisions.md`).
- Расхождение Figma ↔ код у уже перенесённого компонента (`ported`/`verified`) — это не батч на
  потом, это баг: сообщить сразу, не ждать порога.
