# Сборка и запуск скрипта `use_figma`

`use_figma` — JavaScript внутри живого сеанса Figma через Plugin API. Загружай вместе с
официальным скиллом `/figma-use` (у MCP он обязательный) — здесь только то, что специфично для
этого проекта.

## Жёсткие ограничения площадки

- **Нет сетевого доступа.** Скрипт не может скачать что-то снаружи — весь нужный код идёт внутри
  вызова. Экспорт токенов/переменных — через `return`, не через `fetch`.
- **Ответ обрезается на ~20 КБ.** Полный экспорт не влезает в один вызов — гони по коллекциям
  (`ONLY = ["Theme"]` и т.п.), текстовые/эффект-стили отдельным прогоном, собирай результат
  локально по частям.
- **Смена страницы — не чаще раза за вызов.** `await figma.setCurrentPageAsync(page)`, не
  `figma.currentPage = page` (не поддерживается). Если работа на N страницах — N параллельных
  вызовов `use_figma` в одном сообщении, не последовательный цикл внутри одного скрипта.
- **Независимые `await` — батчем через `Promise.all`.** Цикл с `await getVariableByIdAsync(id)`
  на каждой итерации — N последовательных IPC-раундтрипов вместо одного. В этом проекте это была
  реальная проблема: `figma-export.js`/`figma-snapshot.js` брали 267 переменных по одной, хотя
  `getLocalVariablesAsync()` уже отдаёт все объекты разом (см. коммит A1 в истории).

## Дешевле править мастер, чем перебирать варианты

Если правка применима ко всем вариантам набора одинаково (цвет токена, геометрия по оси) — это
правка **мастер-компонента или функции-генератора**, не 48 отдельных `set()`. Генераторы
`figma-foundations.js`/`figma-playground.js` в этом проекте идемпотентны (чистят свою область
перед сборкой) ровно для этого — чтобы перезапуск после правки одного фрагмента был безопасен и
не требовал ручной чистки старого.

## Структура правки, не только размер вызова

Выбирай границу вызова по восстанавливаемости, не по желанию проверить каждый шаг отдельно:
цельная секция или страница — один вызов, если скрипт безопасно повторить при сбое. Дробить —
при пересечении границы страницы, при риске не восстановиться из середины, или после реальной
ошибки, требующей точечного повтора. `use_figma` откатывает весь скрипт при необработанном
исключении — это делает повтор после фикса безопасным, но не гарантией, что часть точно прошла:
проверяй фактическое состояние чтением, не по номеру строки, на которой упала ошибка.

## Возвращай доказательство, не только «готово»

Каждый скрипт, создающий/меняющий узлы, возвращает их ID и релевантные счётчики/границы — это и
есть структурная проверка. Отдельный аудит `get_metadata` — только если этого доказательства не
хватает или после мутации, которая его обесценила. Экономия: не гонять лишний read-only вызов,
если данные уже есть в ответе предыдущего.
