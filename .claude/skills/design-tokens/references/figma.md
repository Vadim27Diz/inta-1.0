# Figma: переменные, стили, компоненты

Инструменты: официальный Figma MCP. Перед любым `use_figma` загрузи скилл `/figma-use` (у MCP он обязательный). Для чтения дизайна в код — `/figma-design-to-code` + `get_design_context`.

## Структура файла

| Страница | Что там |
|---|---|
| `Cover` | название, версия, дата экспорта токенов |
| `Foundations` | образцы всех слоёв, типографика, отступы, радиусы, тени. Собирается генератором, руками не правится — см. «Страница Foundations» |
| `Components` | по секции на компонент, в порядке из `shadcn-mapping.md` |
| `Playground` | 4 рамки бренд × тема для визуальной проверки |

## Коллекции и режимы

| Коллекция | Режимы | Значения | Scopes |
|---|---|---|---|
| `Primitives` | `Value` | сырые: палитра Tailwind (hex), `spacing/*`, `text/*/size`, `text/*/line-height`, `font-weight/*`, `radius/none`, `radius/full`, `font/mono` | цвета — **пусто** (не видны в пикерах); числовые шкалы — свои поля (GAP, FONT_SIZE…) |
| `Brand` | `Main`, `Demo` | `brand/primary/50…950`, `brand/secondary/50…950` (алиасы на Primitives), `brand/*/on`, `font/sans`, `font/heading`, `radius/sm…xl` | рампы — пусто; шрифты — FONT_FAMILY; радиусы — CORNER_RADIUS |
| `Theme` | `Light`, `Dark` | семантические цвета, **только алиасы** на Brand и Primitives | заливки — FRAME_FILL, SHAPE_FILL; `on-*`/`link` — TEXT_FILL, SHAPE_FILL, STROKE_COLOR; `border/*`, `focus-ring` — STROKE_COLOR |
| `Component` | `Value` | `<component>/<token>` — алиасы на Theme | как у Theme |

- Лимит режимов зависит от тарифа Figma: на бесплатном плане нескольких режимов может не быть. Если `addMode` падает — остановись и скажи человеку.
- У каждой переменной code syntax **WEB** = `var(--ds-…)` (по правилам перевода из SKILL.md). Это то, что разработчик видит в Dev Mode.
- Значения в `Theme` и `Component` — **только алиасы**. Hex в этих слоях — ошибка (экспорт её покажет в `_problems`).

## Первичная настройка (пустой файл)

1. `use_figma` с кодом `assets/figma-import.js`, в `SEED` вставь содержимое `assets/tokens.seed.json`. **По одной коллекции за запуск**, порядок: Primitives → Brand → Theme → Component (`ONLY = ["<коллекция>"]`, `TEXT_STYLES = false`). Алиасы резолвятся по имени против того, что уже есть в файле, поэтому порядок обязателен.
   Если `addMode` падает — на тарифе нет нескольких режимов, остановись и скажи человеку: без второго режима ни мультибренд, ни тёмная тема не собираются.
2. **Пятый, отдельный запуск — текстовые стили:** `ONLY = []`, `TEXT_STYLES = true`. Отдельный, потому что стили привязываются к переменным `font/*`, `text/*`, `font-weight/*` из Primitives и Brand — до их создания привязка не к чему.
   Начертания скрипт выбирает по факту из `listAvailableFontsAsync()` и бросает ошибку, если нужного веса нет: у Inter полужирный называется `Semi Bold` (с пробелом), у IBM Plex — `SemiBold`, у JetBrains Mono его нет вовсе. Тихий откат на Regular запрещён — заголовок без веса хуже упавшего запуска.
3. Создай эффект-стили теней `shadow/xs, sm, md, lg, xl` со значениями Tailwind (`shadow-xs … shadow-xl`). Цвет тени — **чёрный прямо в эффекте, с альфой как в Tailwind** (xs — 5 %, остальные — 10 %), не привязанный к переменной: `setBoundVariableForEffect("color", …)` тянет и альфу переменной (у `color/black` она 1.0) и делает тени непрозрачными. Это правило, а не исключение; отдельные токены `color/shadow/*` под каждую альфу не заводим.
4. Собери страницу `Foundations` генератором (раздел «Страница Foundations»).
5. Экспорт (ниже) → `npm run tokens:build` → сверка: значения в `tokens.css` совпадают с Figma.

## Страница Foundations

Собирается генератором `assets/figma-foundations.js`, руками не правится: ручная правка переживёт
ровно до следующей пересборки. Страница — **восемь самостоятельных фреймов верхнего уровня**,
разложенных слева направо и сверху вниз с отступом 160:

| Фрейм | Что внутри | Режимы |
|---|---|---|
| `01 Palette` | слой Primitives: все шкалы с именем и hex | Main / Light |
| `02 Brand` | роль → Main / Demo: primary, secondary, шрифты, радиусы | две ячейки по бренду |
| `03 Color roles` | слой Theme, пары `X` / `on-X` с WCAG и APCA | сетка 2 × 2: колонки Main / Demo, строки Light / Dark |
| `04 Surfaces & single roles` | поверхности с контрастом + роли без пары `on-*` | та же сетка 2 × 2 |
| `05 Typography` | 18 текстовых стилей с метриками | две ячейки по бренду |
| `06 Radius` | `radius/none…full` со значениями бренда | две ячейки по бренду |
| `07 Shadows` | эффект-стили `shadow/xs…xl` | Main / Light |
| `08 Spacing` | 38 токенов `spacing/*`, ширина привязана к переменной | Main / Light |

**Режимы Brand и Theme заданы на каждом фрейме отдельно, а не на общей обёртке** — фрейм можно
скопировать на другую страницу или в другой файл, и он не станет наследовать чужие режимы.

**Правило: после любой правки токенов страницу надо пересобрать.** Заливки, радиусы и шрифты на
ней живые (привязаны к переменным), а подписи — статичный текст: hex примитивов, числа радиусов и
отступов, WCAG и APCA. После `npm run tokens:build` они врут, пока страницу не пересобрали.

Пересборка:

1. `node assets/figma-foundations-data.mjs > /tmp/foundations-data.json` — считает контраст
   (`scripts/check-contrast.mjs --all`) и достаёт из git коммит и дату `tokens/tokens.json`.
2. Вставь содержимое файла в `const DATA` в начале `assets/figma-foundations.js`.
3. Прогони весь `figma-foundations.js` через `use_figma` **одним вызовом**: он сам удаляет
   содержимое страницы `Foundations` и собирает её заново, поэтому перезапуск безопасен.
4. Прогони `assets/figma-foundations-check.js`: `unboundPaints`, `textWithoutStyle`,
   `unboundRadii`, `localEffects`, `textOverflow`, `primitivesInPaints`, `framesWithoutModes` —
   все пустые, `topFrames` — восемь штук, у каждого оба режима.

Что генератор берёт откуда: цвета, радиусы, отступы и метрики текстовых стилей он читает живьём из
переменных и стилей файла (поэтому внутри одной сборки подписи не могут разъехаться с Figma);
WCAG и APCA — только из `DATA`, потому что единственный источник правды по контрасту —
`check-contrast.mjs`, и дублировать его формулы в плагин-скрипте нельзя. В шапке страницы стоят
коммит и дата `tokens.json`, из которых она собрана, — по ним видно, не устарела ли страница.

Hex на странице существует только как **текст подписи**: он документирует значение, а не задаёт
его. Ни одной несвязанной заливки — это и проверяет check-скрипт.

Грабли, на которые генератор уже наступил:

- Плашка фиксированной ширины с подписью внутри («Aa on-primary-subtle») обрезается или наезжает
  на соседа. Поэтому образцы — авто-лейаут, который хватает по содержимому; check-скрипт ловит
  остатки полем `textOverflow`.
- `setExplicitVariableModeForCollection` на рамке с текстом **требует заранее загруженных шрифтов
  обоих брендов** (`IBM Plex Sans/Serif`), иначе падает с «unloaded font» — хотя сам шрифт не
  меняет. То же касается любой правки такой рамки.
- `color/scrim` на тёмной поверхности неразличим без обводки — образцам прозрачных и тёмных
  токенов нужна рамка `color/border/default`.

## Добавление токенов в существующий файл

Файл уже наполнен — значит задача «добавить», а не «импортировать». Три правила.

1. **Add-only скрипт вместо полного импорта.** `assets/figma-import.js` с `ONLY = ["Primitives"]` перезапишет значения, scopes, описания и code syntax **всем** переменным коллекции. Результат обычно тот же, но это запись в существующие объекты: ревью не отличит её от случайной правки, а при расхождении Figma с сидом она молча затрёт Figma. Поэтому пиши короткий скрипт, который создаёт ровно перечисленные объекты, пропускает уже существующие по имени (с записью в лог — тогда перезапуск безопасен) и не делает ни одного `setValueForMode`, `renameMode` или присваивания `scopes` по тому, что уже есть. Scopes и code syntax у новых переменных считай теми же функциями (`primitiveScopes` / `scopesFor`, `var(--ds-…)`), чтобы они не разъехались с остальными.
2. **Снимки хешей до и после.** Перед записью прогони read-only скрипт, который собирает по одной канонической строке на переменную (`имя|тип|значения по режимам|scopes|code syntax|описание`) и на текстовый стиль (`имя|начертание|размер|интерлиньяж|трекинг|привязки`), сортирует и хеширует по коллекциям плюс отдельно по стилям. После записи пересчитай, **исключив новые имена**: хеш каждой коллекции и хеш стилей обязаны совпасть с до-снимком. Это и есть доказательство «добавили, ничего не задели» — счётчики его не дают, они не видят изменения значения или scope. Хеш-функция любая стабильная, лишь бы одинаковая в обоих прогонах (djb2 достаточно).
3. **Проверка `_problems`.** Последним прогоном — `assets/figma-export.js` (можно обрезать финальный `return` до `_problems` и счётчиков, чтобы не тащить весь JSON). Он поймает именно ошибки новых объектов: `ALL_SCOPES`, пустой или не совпадающий с именем code syntax, непривязанное свойство текстового стиля, hex в Theme.

Порядок: снимок → добавление → сверка хешей → `_problems`. Экспорт и `npm run tokens:build` — отдельным шагом, когда правки в Figma закончены.

## Экспорт Figma → код

1. `use_figma` с кодом `assets/figma-export.js` → результат сохрани в `tokens/tokens.json`.
2. Кроме значений экспорт выгружает `scopes`, `codeSyntax` (WEB) у каждой переменной и `effectStyles` (тени) — так дрейф scopes и потеря теней видны в диффе, а не только в Figma. `build-tokens.mjs` эти поля игнорирует.
3. Если в результате непустой `_problems` — сначала исправь в Figma, потом продолжай. Проверки: hex в Theme, алиас на чужой файл, `ALL_SCOPES`, пустой или не совпадающий с именем code syntax, непривязанное свойство текстового стиля.
4. `npm run tokens:build` и, если менялся состав токенов, `npm run tokens:catalog`.
5. **Пересобери `Foundations`** — её подписи (hex, WCAG/APCA, числа радиусов и отступов) статичны и после правки токенов врут.
6. Коммит: `tokens: <что поменялось>`.

## Компоненты в Figma

Один компонент = один **component set**. Свойства совпадают с пропсами кода.

| Свойство Figma | Значения | В коде |
|---|---|---|
| `Variant` | как в cva: `primary`, `secondary`, `neutral`, `outline`, `ghost`, `danger`, `link` | проп `variant` |
| `Size` | `sm`, `md`, `lg`, `icon` | проп `size` |
| `State` | `default`, `hover`, `pressed`, `focus`, `disabled` | **не проп**: CSS-состояния `hover:`, `active:`, `focus-visible:`, `disabled:` |
| boolean `Icon left`/`Icon right`, text `Label` | — | `children`, слоты |

Правила сборки:
- **Auto layout везде.** Padding и gap привязаны к `spacing/*` (числа = шкала Tailwind: `spacing/4` = 16 = `p-4`).
- **Каждая** заливка, обводка и цвет текста привязаны к переменной Theme/Component. Ни одного hex.
- Радиус привязан к `radius/*` из Brand — тогда он меняется вместе с брендом.
- Текст — только текстовые стили, свой на каждый размер (`label/sm` → sm, `label/md` → md, `label/lg` → lg), не ручные размеры.
- Подпись — одна строка: `textAutoResize = WIDTH_AND_HEIGHT`, `textTruncation = ENDING`, `maxLines = 1`, `textAlignHorizontal = CENTER`. Это эквивалент `whitespace-nowrap` в коде (см. «Ловушки Figma»).
- Состояние `focus` = копия `default` + **отдельный слой `focus-ring`**: прямоугольник на 4px больше кнопки, absolute-позиционирование с constraints STRETCH, обводка 2px `color/focus-ring` снаружи, без заливки, радиус `radius/lg`. Это `outline-2 outline-offset-2` из кода: 2px прозрачного зазора, потом 2px кольца. Фон в focus не меняется. Почему не тени — в «Ловушках Figma».
- Состояние `disabled`: `color/disabled` + `color/on-disabled`. **Исключение — текстовые варианты** (`link`, `link-danger`): у них фона нет и в disabled, меняется только цвет текста на `color/on-disabled` (в коде это `disabled:bg-transparent`). Вариант с обводкой в disabled обводку **не снимает**, а делает её прозрачной — иначе кнопка станет на 2px уже остальных состояний.
- Слои названы как части кода: `root`, `icon-left`, `label`, `icon-right` (уровни element из статьи).
- Иконки — компоненты-инстансы с цветом от `on-*` токена родителя.

## Иконки

Один компонент = один глиф. Источник — пакет `lucide-static` **той же версии, что `lucide-react`**
в проекте (сейчас 1.57.0): иначе рисунок в Figma и в браузере разъедутся на отдельных иконках.

| Объект | Что это |
|---|---|
| `li:<имя>` | глиф 24×24, `clipsContent = true`, **один слой `Vector`** |
| `Icon base` | мастер 24×24 с экземпляром глифа и свойством `glyph` (INSTANCE_SWAP, preferred values — все `li:*`) |
| `Icon` | набор со свойством `Size` = 12/16/20/24/32/40 (= `size-3/4/5/6/8/10`); каждый вариант — экземпляр мастера, `rescale(N/24)` |

Как делается глиф: `createNodeFromSvg(svg)` → у каждого потомка `outlineStroke()` → `figma.flatten(...)`
в один `Vector` → `strokes = []`, заливка привязана к `color/on-surface`, `constraints = SCALE`.
**Обводка переводится в заливку намеренно:** тогда толщина — это геометрия, и при `rescale` она
масштабируется ровно как в браузере, где SVG с `viewBox 0 0 24 24` и `stroke-width: 2` рисуется
толщиной `2 × size / 24`. Проверка цифрами — `npm run icons:stroke` (меряет настоящий Chrome
через `isPointInStroke` и по пикселям) против высоты bbox слоя `Vector` у глифа `li:minus`.

Цвет иконки — заливка слоя `Vector`. В компоненте её переопределяют на свой `on-*` токен,
и переопределение **переживает замену глифа**, потому что слой во всех глифах называется одинаково
(`Vector`). Это надо проверять после любой пересборки набора глифов.

В коде `Icon` нет: иконки берутся из `lucide-react` напрямую, размер — классом `size-*`
(`[&_svg]:size-4` у кнопки = `Icon Size=16`).

## Ловушки Figma

Найдены на кнопке, стоили больше времени, чем сама сборка. Проверяй их до того, как начнёшь спорить со своими глазами.

### Тени

1. **`clipsContent = false` полностью отключает тени на фрейме.** Границы ноды (`absoluteRenderBounds`) при этом
   честно растут на spread, а на холсте не появляется ничего. Если тень «не рисуется» — первым делом включи Clip content.
   У прямоугольников этого эффекта нет, только у фреймов и компонентов, поэтому проба на прямоугольнике ничего не покажет.
2. **Эффекты рисуются в обратном CSS порядке: последний в массиве — сверху.** В `box-shadow` первым идёт тот, что ближе
   к элементу; в Figma — наоборот. Кольцо фокуса `ring-offset-2 ring-2` собирается как `[spread 4 (кольцо), spread 2 (отступ)]`.
3. **Нода без заливки тень не отбрасывает вовсе.** Тень строится по силуэту ноды, а у `fills: []` силуэта нет —
   не помогает ни `showShadowBehindNode`, ни заливка с `opacity: 0`. Прозрачные варианты (`ghost`, `link`, `outline`)
   тени не дают в принципе.
4. **Контейнер с кнопками не должен обрезать кольцо.** Кольцо живёт 4px снаружи ноды, а у фрейма Clip content включён
   по умолчанию. У любого контейнера с компонентами (рамки Playground, ряды внутри них, component set) либо выключай
   Clip content, либо давай внутренний отступ ≥ 4px. Иначе фокус выглядит обрезанным ровно по краю ряда.
   То же и у самой кнопки: слой кольца выходит за её границы, поэтому `clipsContent = false`.

### Кольцо фокуса: почему слоем, а не тенями

Тенями его собрать можно (`[spread 4 — цвет кольца, spread 2 — цвет подложки]`), и ровно так оно сначала и было
сделано. Это ошибка: тень непрозрачна, поэтому зазор приходится красить в `color/surface`, и на карточке
`surface-raised` кнопка выкладывает вокруг себя заплатку цвета страницы. Плюс прозрачные варианты вообще остаются
без кольца (п. 3), и их приходится заливать той же `surface`.

**Правильно — отдельный слой `focus-ring`:** прямоугольник на 4px больше кнопки (по 2px на сторону), absolute
с constraints STRETCH (растёт вместе с кнопкой), обводка 2px снаружи, без заливки. Зазор остаётся прозрачным и
показывает подложку, какой бы она ни была. В коде этому соответствует `outline-2 outline-offset-2`, а не `ring`.

**Радиус кольца.** Chrome рисует `outline` со скруглением «радиус кнопки + offset»: для кнопки с `radius/md` и
offset 2 внутренний радиус кольца 8, внешний 10 (проверено попиксельным сравнением — совпадение с рамкой
`border-radius: 10px` без единого отличающегося пикселя). Выразить «радиус + 2» привязкой к переменной нельзя,
поэтому слой привязан к `radius/lg`: в Main это ровно 8, в Demo — 4 вместо нужных 5. **Расхождение на 1px по углам
кольца в бренде Demo** — известное и допущенное.

### Варианты и текст

5. **Правка текстового свойства размножается по всем вариантам набора.** Меняешь `textDecoration` у одного варианта —
   Figma применяет её ко всем соседям с тем же слоем, и через Plugin API тоже. Поэтому подчёркивание только в hover
   у `link` не выражается: последняя запись выигрывает и растекается. Отсюда правило — **`link` и `link-danger` без
   подчёркивания во всех состояниях, в Figma и в коде; при hover меняется только цвет.** Всё, что должно отличаться
   по состояниям, задавай **до** `combineAsVariants`.
6. **Подпись сама по себе многострочна.** Если в текстовое свойство `Label` попадёт перевод строки (а он попадёт:
   достаточно нажать Enter при редактировании), текст разложится в несколько строк, кнопка вырастет по высоте мимо
   привязанной `height`, а при выравнивании LEFT получится рваный левый край. Лечится на мастер-компоненте:
   `textTruncation = "ENDING"` + `maxLines = 1` (это `whitespace-nowrap`) и `textAlignHorizontal = "CENTER"`
   (чтобы подпись осталась по центру, даже если кто-то поставит её в Fill).
7. **`defaultVariant` набора задать нельзя.** Figma берёт левую верхнюю ячейку сетки. Если в коде
   `defaultVariants.size = "md"`, а в сетке первый ряд `sm`, экземпляр из панели ассетов придёт со `sm`.
   Либо переставляй ряды, либо считай это известным расхождением.

### Компоненты и свойства

9. **У скрытого экземпляра нет вложенных детей.** Поставил `instance.visible = false` — и
   `instance.children` возвращает пустой массив, а `findOne` ничего не находит: Figma не
   материализует поддерево невидимого экземпляра. Поэтому глиф, цвет и любые оверрайды задавай
   **до** того, как прячешь экземпляр (у кнопки иконки по умолчанию скрыты свойством `Icon left`).
10. **`addComponentProperty(..., "INSTANCE_SWAP", ...)` хочет id ноды, а не ключ компонента.**
    С `component.key` падает `Property value is incompatible with component property type`.
    `preferredValues` при этом задаются именно ключами: `[{ type: "COMPONENT", key: c.key }]`.
11. **Вложенное свойство живёт на вложенном экземпляре.** У экземпляра варианта `Icon` в
    `componentProperties` только `Size`; свойство `glyph` — у его ребёнка (экземпляра `Icon base`),
    и `setProperties` надо звать на нём.
12. **Набор вариантов не раскладывает сам себя.** `combineAsVariants` складывает варианты в стопку.
    Удобная сетка — переставить детей в нужном порядке (`appendChild` по порядку) и включить
    `layoutMode = "HORIZONTAL"` + `layoutWrap = "WRAP"` с фиксированной шириной набора: колонки
    получаются по первому свойству, строки — по остальным.
13. **`use_figma` может начать отвечать `// truncated to 20kb` на любой, даже пустой скрипт.**
    Это залипший мост, а не ошибка скрипта: правки при этом **не применяются** (проверяется
    `get_metadata` — он продолжает работать). Лечится перезапуском плагина Figma MCP; дождись
    ответа на `return 1;` прежде чем гнать дальше запись.

### Экспорт

8. **Полный экспорт не влезает в один ответ `use_figma`** (лимит ~20 КБ). Гони по коллекциям (`ONLY`), текстовые
   и эффект-стили — отдельным прогоном, и собирай `collections` локально.

## Проверка бренда и темы

На странице `Playground` четыре рамки. Каждой задай режимы явно (в UI: панель Appearance → иконка переменных; в Plugin API: `frame.setExplicitVariableModeForCollection(collection, modeId)`):

| Рамка | Brand | Theme |
|---|---|---|
| Main / Light | Main | Light |
| Main / Dark | Main | Dark |
| Demo / Light | Demo | Light |
| Demo / Dark | Demo | Dark |

Положи в каждую экземпляры компонента. Если что-то не перекрасилось — значит, там не переменная.

## Figma → код для одного компонента

1. `get_design_context` по ноде component set (после `/figma-design-to-code`). Результат — ориентир, не готовый код.
2. Сопоставь каждую переменную из `get_variable_defs` с классом по таблице из SKILL.md.
3. Код берётся из shadcn (`shadcn-mapping.md`), а Figma задаёт варианты, размеры и токены. Расхождения Figma vs shadcn — по Figma; вопросы — человеку.
4. Сравни `get_screenshot` с историей Storybook в той же комбинации бренд × тема.
