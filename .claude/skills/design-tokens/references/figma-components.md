# Figma: сборка компонентов, иконки, раскладка страниц

Переменные и токены — в `figma-variables.md`, ловушки Plugin API — в `figma-pitfalls.md`. Этот
файл — про сам компонент: свойства, иконки, правило раскладки страницы Components, страница
Playground, сверка бренда/темы, перенос Figma → код.

## Компоненты в Figma

Один компонент = один **component set**. Свойства совпадают с пропсами кода.

| Свойство Figma | Значения | В коде |
|---|---|---|
| `Variant` | как в cva: `primary`, `secondary`, `neutral`, `outline`, `ghost`, `danger`, `link` | проп `variant` |
| `Size` | `sm`, `md`, `lg`, `icon` | проп `size` |
| `State` | `default`, `hover`, `pressed`, `focus`, `disabled` | **не проп**: CSS-состояния `hover:`, `active:`, `focus-visible:`, `disabled:` |
| boolean `Icon left`/`Icon right`, text `Label` | — | `children`, слоты |

Правила сборки:
- **Auto layout везде.** Padding и gap привязаны к `spacing/*` (числа = шкала Tailwind: `spacing/4` = 16 = `p-4`).
- **Каждая** заливка, обводка и цвет текста привязаны к переменной Theme/Component. Ни одного hex.
- Радиус привязан к `radius/*` из Brand — тогда он меняется вместе с брендом.
- Текст — только текстовые стили, свой на каждый размер (`label/sm` → sm, `label/md` → md, `label/lg` → lg), не ручные размеры.
- Подпись — одна строка: `textAutoResize = WIDTH_AND_HEIGHT`, `textTruncation = ENDING`, `maxLines = 1`, `textAlignHorizontal = CENTER`. Это эквивалент `whitespace-nowrap` в коде (см. «Ловушки Figma»).
- Состояние `focus` = копия `default` + **отдельный слой `focus-ring`**: прямоугольник на 4px больше кнопки, absolute-позиционирование с constraints STRETCH, обводка 2px `color/focus-ring` снаружи, без заливки, радиус `radius/lg`. Это `outline-2 outline-offset-2` из кода: 2px прозрачного зазора, потом 2px кольца. Фон в focus не меняется. Почему не тени — в «Ловушках Figma».
- Состояние `disabled`: `color/disabled` + `color/on-disabled`. **Исключение — текстовые варианты** (`link`, `link-danger`): у них фона нет и в disabled, меняется только цвет текста на `color/on-disabled` (в коде это `disabled:bg-transparent`). Вариант с обводкой в disabled обводку **не снимает**, а делает её прозрачной — иначе кнопка станет на 2px уже остальных состояний.
- Слои названы как части кода: `root`, `icon-left`, `label`, `icon-right` (уровни element из статьи).
- Иконки — компоненты-инстансы с цветом от `on-*` токена родителя.

## Иконки

Один компонент = один глиф. Источник — пакет `lucide-static` **той же версии, что `lucide-react`**
в проекте (сейчас 1.57.0): иначе рисунок в Figma и в браузере разъедутся на отдельных иконках.

| Объект | Что это |
|---|---|
| `li:<имя>` | глиф 24×24, `clipsContent = true`, **один слой `Vector`** |
| `Icon base` | мастер 24×24 с экземпляром глифа и свойством `glyph` (INSTANCE_SWAP, preferred values — все `li:*`) |
| `Icon` | набор со свойством `Size` = 12/16/20/24/32/40 (= `size-3/4/5/6/8/10`); каждый вариант — экземпляр мастера, `rescale(N/24)` |

Как делается глиф: `createNodeFromSvg(svg)` → у каждого потомка `outlineStroke()` → `figma.flatten(...)`
в один `Vector` → `strokes = []`, заливка привязана к `color/on-surface`, `constraints = SCALE`.
**Обводка переводится в заливку намеренно:** тогда толщина — это геометрия, и при `rescale` она
масштабируется ровно как в браузере, где SVG с `viewBox 0 0 24 24` и `stroke-width: 2` рисуется
толщиной `2 × size / 24`. Проверка цифрами — `npm run icons:stroke` (меряет настоящий Chrome
через `isPointInStroke` и по пикселям) против высоты bbox слоя `Vector` у глифа `li:minus`.

Цвет иконки — заливка слоя `Vector`. В компоненте её переопределяют на свой `on-*` токен,
и переопределение **переживает замену глифа**, потому что слой во всех глифах называется одинаково
(`Vector`). Это надо проверять после любой пересборки набора глифов.

В коде `Icon` нет: иконки берутся из `lucide-react` напрямую, размер — классом `size-*`
(`[&_svg]:size-4` у кнопки = `Icon Size=16`).

## Раскладка страницы Components

Правило, которое проверяет `npm run figma:layout` (снимок — `assets/figma-layout-export.js` → `figma/layout.json`):

1. На верхнем уровне страницы — **только секции**. Ни одного компонента, набора или фрейма рядом с ними.
2. Каждый компонент и каждый component set лежит **внутри секции**.
3. Внутри секции: `title` (стиль `heading/4`, `color/on-surface`), `description` (`body/sm`, `color/on-surface-muted`), затем набор. Отступ от рамки секции — **ровно 64** со всех четырёх сторон, размер секции считается по содержимому.
4. Секции — **в одну колонку**: одинаковый x, зазор **160** между рамками, порядок сверху вниз как в `shadcn-mapping.md`: Button, Icon, Icon / Glyphs, Label, Input, Textarea…
5. Рамки секций **не пересекаются**.
6. Глифы иконок живут в отдельной секции `Icon / Glyphs`: сетка с шагом **64** по обеим осям, под каждым глифом подпись-имя (`caption-2xs`, `color/on-surface-muted`), по центру ячейки.
7. **В наборах компонентов нет абсолютно позиционированных слоёв, кроме `focus-ring`.** Курсор и всё, что зависит от длины текста, — только в потоке auto layout (сосед по flow, не координатами). Если слою всё же нужно выйти за рамку варианта (как кольцу фокуса — оно на 2px больше поля с каждой стороны), он остаётся `layoutPositioning = ABSOLUTE`, и только он.
8. **Ни один `focus-ring` нигде не обрезан предком — на Components, Playground и Foundations.** `clipsContent=true` у предка допустим, только если кольцо (оно на 2px больше поля с каждой стороны) целиком помещается внутри его рамки — не блокирующий запрет `clipsContent` вообще, только проверка вместимости. Снимается отдельным проходом по каждой из 3 страниц (переключение страницы — не чаще раза за вызов `use_figma`), находки суммируются в `ringClipping`.
9. **Контейнер текстового слоя — только Hug или Fill по ширине, никогда Fixed.** Фиксированная ширина либо обрежет длинный контент, либо не даст короткому сжаться — ровно так ломался Kbd (ширина 20 всегда, «K+⌘» вылезал за рамку). Исключения — `Input`/`Textarea` (`field`): фиксированная ширина там по дизайну, переполнение клипуется краем поля без многоточия — это не баг, см. «Раскладка страницы Components» выше про курсор в потоке auto layout.
10. **Текст, который меняется при использовании (подпись, значение, клавиша), подключён как component property `TEXT`, не «голый» текстовый слой.** Голый текст нечем переопределить с инстанса — ровно так было у Badge (9 вариантов, литеральный текст = имя варианта вместо единого свойства `Text`, как у Button/Label/Input) и у Kbd. Исключение — декоративный маркер обязательности Label (`*`): всегда литеральный символ, не пользовательский контент.
11. **Дочерние элементы списка (пункт Select, позже menu item/command item) — ширина Fill, не Hug.** Список — вертикальный auto layout с 2+ детьми-инстансами одного компонента; у каждого инстанса `layoutSizingHorizontal` должна быть `FILL`, иначе подсветка состояния (hover/highlighted) тянется только по ширине текста, а не на всю ширину панели — ровно так было у Select до ревью: «Банан» уже, чем «Яблоко», справа пустая полоса.
12. **Повторяющиеся элементы внутри компонента (пункты списков, вкладки, ячейки) — экземпляры общего компонента, а не нарисованные слои.** 2+ соседних слоя с одинаковым именем, ни один не `INSTANCE` — повод вынести в переиспользуемый компонент (`Select / Item`, `Input OTP / Slot`). Компонент можно сделать локальным для одного родителя сначала, выносить в общую основу — когда понадобится 2+ родителям.

**Координаты детей секции относительные** — как у фрейма, от левого верхнего угла секции. Это главная
ловушка: `node.x = section.x + 64` уводит ребёнка на `section.x` вправо, секция выглядит пустой, а её
содержимое уезжает на соседей. Сравнивать и проверять — только по `absoluteBoundingBox`.

## Страница Playground

Собирается генератором `assets/figma-playground.js`, руками не правится — так же, как Foundations.
Пересборка — после добавления компонента в группу: допиши вариант в нужный блок генератора и прогони
скрипт целиком, он идемпотентен (чистит все 4 фрейма перед сборкой).

**Назначение страницы — быстрая проверка бренд × тема, не каталог.** Каталог — страница Components
и Storybook. Поэтому в Playground каждый компонент встречается в каждом контексте (surface /
surface-raised / выборка / витрина / иконки) **ровно один раз** — не повторяй один и тот же набор
вариантов в нескольких местах страницы, даже если кажется удобным «показать ещё раз рядом».

Структура одинакова во всех **4 фреймах верхнего уровня** (Main/Light, Main/Dark, Demo/Light,
Demo/Dark), расставленных сеткой 2×2 с отступом **160**:

1. **Buttons** — 10 вариантов в `default` одним рядом на `surface`. Состояния
   `default/hover/pressed/focus/disabled` и размеры `sm/md/lg/icon` — только у `primary`
   (у остальных вариантов тот же код путь, достаточно проверить на одном).
2. **Одна карточка `surface-raised`** на фрейм (обводка `color/border/default` 1px, подпись
   «на surface-raised» — иначе в Main/Light карточка неотличима от страницы, см. ловушку ниже) —
   всё, что проверяет «заплатки» под приподнятой поверхностью: `outline`/`ghost`/`link` в фокусе,
   `Label` + `Input` (value), `Input invalid`, `Input disabled`, `Textarea focus` (с курсором).
3. **Selection** — Checkbox, Radio Group, Switch: выкл / вкл / disabled, по одному ряду на компонент.
4. **Display** — Badge (все варианты одним рядом), разделитель `horizontal` на всю ширину ряда,
   под ним Kbd, Spinner, Skeleton одним рядом (разделитель `vertical` рядом с 16-пиксельной иконкой
   давал на вид пустой прямоугольник — вынесен отдельной полной строкой).
5. **Icons** — 4–5 глифов одним размером (`Size=16`).

Раскладка внутри каждого фрейма — **только auto layout** (`row`/`sectionFrame`, оба через общий
`newFrame()` — см. «Топ ловушек» в SKILL.md, пункт про `clipsContent` по умолчанию), без единой
ручной координаты; у секций подпись — стиль `caption`, `color/on-surface-muted`. Исключение — сами
4 фрейма верхнего уровня: их позиция на странице (сетка 2×2) задаётся абсолютными x/y, и это
нормально — это позиция страницы, не внутренность компонент-сета (правило про отсутствие абсолютных
слоёв — из раздела «Раскладка страницы Components» — сюда не относится).

`npm run figma:layout` покрывает на этой странице одно правило — ни один `focus-ring` нигде не
обрезан предком (то же правило, что и на Components, прогоняется отдельным проходом по этой
странице и суммируется в снимке `figma/layout.json` → `ringClipping`). Остальное — глазами,
скриншотом каждого из 4 фреймов после пересборки.

## Проверка бренда и темы

На странице `Playground` четыре рамки. Каждой задай режимы явно (в UI: панель Appearance → иконка переменных; в Plugin API: `frame.setExplicitVariableModeForCollection(collection, modeId)`):

| Рамка | Brand | Theme |
|---|---|---|
| Main / Light | Main | Light |
| Main / Dark | Main | Dark |
| Demo / Light | Demo | Light |
| Demo / Dark | Demo | Dark |

Положи в каждую экземпляры компонента. Если что-то не перекрасилось — значит, там не переменная.

## Figma → код для одного компонента

1. `get_design_context` по ноде component set (после `/figma-design-to-code`). Результат — ориентир, не готовый код.
2. Сопоставь каждую переменную из `get_variable_defs` с классом по таблице из SKILL.md.
3. Код берётся из shadcn (`shadcn-mapping.md`), а Figma задаёт варианты, размеры и токены. Расхождения Figma vs shadcn — по Figma; вопросы — человеку.
4. Сравни `get_screenshot` с историей Storybook в той же комбинации бренд × тема.
