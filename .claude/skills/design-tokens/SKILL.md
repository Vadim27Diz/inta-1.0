# Дизайн-токены ds: Figma → tokens.json → Tailwind → Storybook

Мультибрендовая (white-label) система со светлой и тёмной темой. Источник правды — **Figma Variables**.
Логика имён — статья N. Curtis «Naming Tokens in Design Systems», адаптированная под Figma и Tailwind v4 (см. `references/naming.md`).
Компоненты — набор shadcn/ui, переписанный на наши токены (см. `references/shadcn-mapping.md`).

## Золотые правила (нарушение = задача не выполнена)

1. **Компонент использует только семантические токены** (слой Theme или Component). Никаких hex/rgb/oklch, никакой палитры Tailwind (`bg-blue-500`), никаких произвольных значений (`w-[123px]`, `text-[13px]`).
2. **Никаких `dark:` и проверок бренда в компонентах.** Тема и бренд переключаются заменой значений токенов, а не классами.
3. **Состояния — отдельные токены, а не прозрачность.** `hover:bg-primary-hover`, `active:bg-primary-pressed`. Не `bg-primary/90`, не `disabled:opacity-50`.
4. **Контент на поверхности — токен с префиксом `on-`:** `bg-primary text-on-primary`, `bg-surface-raised text-on-surface-raised`.
5. **Disabled и focus общие для всех контролов:** `disabled:bg-disabled disabled:text-on-disabled`, `focus-visible:ring-2 focus-visible:ring-focus-ring`.
6. **Отступы и размеры — шкала Tailwind** (`p-4` = 16px, шаг 4px). В Figma — переменные `spacing/*` с теми же числами.
7. **Текст — стили `typo-*`** (`typo-heading-1`, `typo-body-md`, `typo-label-md`…), 1:1 с текстовыми стилями Figma. Допустимы `text-xs…text-6xl` + `font-medium` и т.п. внутри компонентов, если нужен только размер.
8. **Нет нужного токена → не выдумывай значение.** Сначала локальный токен компонента (слой Component, `<component>/<name>`); когда он нужен 3+ компонентам — повышай в Theme. Новый токен сначала появляется в Figma, затем экспорт и сборка (раздел «Как добавить токен»).
9. **CSS токенов генерируется**, руками `tokens.css` не правим.

## Архитектура: 4 слоя = 4 коллекции Figma

| Слой | Коллекция Figma | Режимы | В коде | Кто использует |
|---|---|---|---|---|
| 1. Primitives | `Primitives` (скрыта из публикации, scopes пустые) | — | `--ds-color-blue-600` | только слой Brand/Theme |
| 2. Brand | `Brand` | `Main` (синий + фиолетовый), `Demo` (бирюзовый + оранжевый) | `[data-brand="main"]` | только слой Theme |
| 3. Theme | `Theme` | `Light`, `Dark` | `:root` / `.dark` | **компоненты** |
| 4. Component | `Component` | — (алиасы на Theme) | `--ds-sidebar-surface` | **один компонент или группа** |

Полный список токенов: `references/token-catalog.md` (сгенерирован, всегда сверяйся с ним).

## Как одно имя живёт в трёх местах

| Figma variable | CSS-переменная | Класс Tailwind |
|---|---|---|
| `color/primary/default` | `--ds-color-primary` | `bg-primary` |
| `color/primary/hover` | `--ds-color-primary-hover` | `hover:bg-primary-hover` |
| `color/on-primary` | `--ds-color-on-primary` | `text-on-primary` |
| `color/border/input` | `--ds-color-border-input` | `border-border-input` |
| `sidebar/hover` | `--ds-sidebar-hover` | `bg-sidebar-hover` |
| text style `heading/1` | — | `typo-heading-1` |

Правила перевода: `/` → `-`; хвост `/default` отбрасывается (в Figma явный, в коде усечённый); префикс `ds` есть у CSS-переменных и code syntax в Figma, но **не у классов** (так shadcn-компоненты переносятся без префиксов в каждом классе); категория `color-` в классе отбрасывается, потому что её уже называет утилита (`bg-`, `text-`, `border-`).

## Порядок работы (pipeline)

Пустой файл первичной настройки — `references/figma-variables.md`. Для обычной работы два
раздельных процесса, не один сквозной список: правка токена целиком — скилл `inta-token-change`;
компонент (Figma → утверждаю → код → истории → docs) — скилл `inta-component-cycle`, с остановкой
между половинами на «переносим?» (`inta-port-queue`). Запись в Figma в обоих случаях — по
протоколу `figma-write-protocol`.

Готово — только если закрыт весь Definition of done ниже. Пример всего цикла на кнопке:
`examples/button.md`.

## Definition of done для компонента

Компонент готов, когда выполнено всё; «почти всё» — это не готово.

| # | Что | Чем проверяется |
|---|---|---|
| 1 | Component set в Figma: свойства 1:1 с пропсами кода, дефолтный вариант = `defaultVariants` кода (Figma берёт левую верхнюю ячейку) | глазами + `componentPropertyDefinitions` |
| 2 | Каждая заливка, обводка, радиус, отступ и текст привязаны к переменной или стилю; фокус — слой `focus-ring` | `npm run figma:layout`, экспорт `_problems` |
| 3 | Набор лежит в своей секции по правилу раскладки (заголовок, описание, отступ 64, колонка с шагом 160) | `npm run figma:layout` |
| 4 | Код: только семантические токены и шкала Tailwind, никаких `dark:`, прозрачностей вместо состояний, произвольных значений; ни один класс не опечатан (иначе Tailwind молча его не соберёт) | `npm run tokens:check` и `npm run tailwind:check` → 0 ошибок |
| 5 | Контраст пар `X` / `on-X` во всех состояниях × 4 комбинации | `npm run tokens:contrast` → 0 ошибок |
| 6 | Истории `Default`, `Variants`, `States`, `Content`, `BrandMatrix`; `Content` — длинный текст, слово без пробелов, пустое значение, placeholder, ошибка; `BrandMatrix` — 4 комбинации × `surface` и `surface-raised` | `npm run visual`, глазами |
| 7 | Числа Figma и кода сходятся: геометрия, токены, шрифт, кольцо фокуса — в 4 комбинациях | `npm run figma:diff` → 0 расхождений |
| 8 | Фокус с клавиатуры виден и одинаков на `surface` и `surface-raised` | `npm run visual`, Tab в Storybook |
| 9 | Перед слиянием ветки — снимок `figma/layout.json` переснят заново и `npm run verify` прогнан после этого | `npm run figma:layout` (режим сохранения), затем `npm run verify` |

Пункты 3–5 и 7 закрываются одной командой: **`npm run verify`**. `npm run visual` в неё не входит —
снимки нужны глазам, а не CI. Токены менялись → ещё и пересборка `Foundations` (см. `references/figma-variables.md`).
Пункт 9 — отдельно от обычной работы над одним компонентом, и про него (что проверяет снимок,
когда он считается устаревшим, `figma:pull` или `use_figma`) — скилл `inta-figma-snapshot`.

## Топ ловушек

Каждая — стоила реального бага на ревью, не гипотетическая. Подробности — `references/figma-pitfalls.md`.

1. **Кольцо фокуса нельзя обрезать.** `clipsContent=true` у любого предка `focus-ring` — только если
   кольцо (оно на 2px больше поля с каждой стороны) целиком помещается внутри его рамки.
2. **Текстовый контейнер — Hug или Fill, никогда Fixed.** Фиксированная ширина с текстом внутри —
   либо обрежет длинный контент, либо не даст короткому сжаться. Исключение — поле ввода
   (Input/Textarea): фиксированная ширина там по дизайну, переполнение клипуется краем поля.
3. **Курсор и всё, что зависит от длины текста, — только в потоке auto layout.** Не абсолютными
   координатами: правильный расчёт один раз для одного текста ломается при любом другом.
4. **Координаты детей SECTION относительные, как у фрейма** — не абсолютные. `absoluteBoundingBox`
   для проверки, не `x`/`y` напрямую.
5. **`data-*`-атрибуты shadcn сверяй с установленным Radix.** CLI генерирует разметку под одну
   версию Radix; другая версия может отдавать другой набор атрибутов (`data-state` вместо
   `data-checked`, например) — без сверки классы просто не сработают.
6. **Новый фрейм в Figma по умолчанию `clipsContent: true`.** Ряд ровно по высоте контента режет
   тень и кольцо фокуса, которые выходят за его границы. Создавай фреймы через общий helper
   (`newFrame()` в генераторах), который сразу ставит `false`, а не раскидывай `clipsContent = false`
   по каждому месту создания вручную — забудешь хоть одно, и ловушка вернётся.
7. **Повторяющиеся элементы (пункты списков, вкладки, ячейки) — экземпляры общего компонента, а не
   нарисованные слои**, и их ширина внутри списка — **Fill, не Hug** (иначе подсветка состояния тянется
   только по тексту, а не на всю ширину панели — как было у Select до ревью). Общий компонент можно
   сначала сделать локальным для одного родителя (`Select / Item`, `Input OTP / Slot`) — выносить в
   переиспользуемую основу (`Menu / Item`) только когда понадобится 2+ родителям, по той же логике, что
   у токенов (правило 8 выше).
8. **Исключения `figma:layout` (`EXEMPT_FIXED_WIDTH`, `EXEMPT_NAKED_TEXT`) ключуются по имени КОРНЕВОГО
   компонента, не варианта.** `ownerName()` в `figma-layout-export.js` возвращает `root.name`
   («Input», «Select / Item») только если ему явно передать его, а не `v.name` (вариант вида `Size=md,
   State=default` — такое в ключе исключения никогда не совпадёт). Это реальный баг, который тихо ломал
   3 существующих исключения (Input/Textarea/Native Select) — проверка показывала «0 нарушений» только
   потому, что закоммиченный `figma/layout.json` не пересобирался после рефакторинга `ownerName`.
9. **Порталы.** Radix `Portal` рендерит контент (`SelectContent` и т.п.) в `document.body`, вне
   DOM-дерева своей обёртки — локальный `data-brand`/`dark` на обёртке (в том числе в истории
   `BrandMatrix`) до него не доходит, действует только то, что стоит на `<html>` (глобальный тулбар
   Storybook). Обёртка над любым Radix-примитивом с порталом принимает проп `container` и передаёт
   его в `<…Primitive.Portal container={container}>`; `BrandMatrix` даёт свою ячейку как `container`
   через `ref`/`useState`, иначе её портал покрасится не в ту ячейку, где нарисован (см. `code.md` →
   «Как переключаются бренд и тема» и шаблон `BrandMatrix` там же; эталон — `select.tsx`).

**Правило:** каждая ловушка, найденная на ревью, получает проверку в `npm run verify` — не только
запись в этом списке. Если проверка невозможна (нет числового критерия) — минимум пункт в
Definition of done с явным «проверяется глазами».

## Как добавить токен

Решение уровня (`Component` vs `Theme`), имя по формуле, add-only запись в Figma со сверкой
хешей, экспорт и пересборка `Foundations` — скилл `inta-token-change`. Здесь — только правило,
не процедура: новый токен сначала появляется в Figma, затем экспорт и сборка, никогда в обратном
порядке.

## Когда спрашивать человека

- Нужен новый **глобальный** (Theme) токен или новый бренд.
- Дизайн в Figma противоречит правилам (например, hex вместо переменной, прозрачность вместо hover-токена) — покажи место и предложи токен, не исправляй молча.
- В режимах получился плохой контраст текста (`on-*` к своей поверхности ниже 4.5:1).
