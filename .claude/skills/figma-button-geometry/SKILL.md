# Button в Figma: геометрия по Type × Size

Применяется к набору Button дизайн-системы Inta 1.0 (Figma fileKey uUb84csG4wOfbUjB38ODiz). Перед записью в Figma: /figma-use, create_session, версия файла сохранена пользователем («версия сохранена»), чужие объекты не удалять и не переписывать без вопроса. Общие правила для всех компонентов (порядок значений, размеры у связанных компонентов): навык figma-component-conventions.

## Структура набора

300 вариантов: 10 Variant × 6 Size × 5 State. Свойство Type делит Size: `Type=Button` (lg, md, sm) и `Type=Icon Button` (icon-lg, icon, icon-sm). Имя варианта начинается с `Type=Button, ` или `Type=Icon Button, `. Любое новое свойство набора меняет имена вариантов: после него обязательно пересобрать снимок `figma/layout.json` и перечитать набор живьём, не доверять старым снимкам.

## Правила

- Ширина, высота и паддинги одинаковы у всех Variant и State внутри одной пары Type × Size. Различается только то, что задаёт Variant (цвет, фон, обводка), не геометрия.
- Ни один паддинг Button не равен 0. Все значения только через переменные `spacing/*`, не хардкод и не подгонка на глаз.
- Вертикальный паддинг Type=Button и паддинг со всех сторон Icon Button считаются по контенту: (Fixed-высота или квадрат − max(line-height текста, высота иконки)) / 2, затем ближайший токен. Если точного токена нет, остановиться и спросить, новый не выдумывать.
- `Type=Icon Button`: жёсткий квадрат (ширина = высота = Size: icon-sm 32, icon 36, icon-lg 40), паддинг со всех сторон, sizing FIXED по обеим осям.
- `Type=Button`: ширина Hug по контенту, высота Fixed по Size (sm 32, md 36, lg 40). Горизонтальный паддинг sm 12, md 16, lg 24 (spacing/3, /4, /6).
- Принятые значения: Button sm и lg вертикаль 8 (spacing/2), md 8 (spacing/2); Icon Button icon-sm 8 (spacing/2), icon и icon-lg 10 (spacing/2-5). Иконка: 16/16/20 для sm/md/lg и 16/16/20 для icon-sm/icon/icon-lg. Высота строки текста: 16/20/24.
- `strokesIncludedInLayout = false` на любом варианте с видимой обводкой (strokes.length > 0), даже при Fixed-размере: Figma иначе прибавляет толщину обводки к размеру (Variant=outline был шире на 2px), а в CSS border рисуется внутри размера. На вариантах без обводки флаг может быть true, он не действует.

## Порядок значений свойств

- Size в панели Properties и в сетке набора идёт от большего к меньшему: для Type=Button lg, md, sm; для Icon Button icon-lg, icon, icon-sm. Хаотичный порядок (md, sm, lg) недопустим.
- Type: Button, Icon Button. Variant и State в порядке, принятом в коде и документации, без случайной перестановки.
- Факт из практики: порядок значений в выпадающем списке Figma хранит по порядку создания значения; перестановка слоёв и позиций вариантов в сетке порядок в списке не меняла (проверено на Button). Поэтому порядок задавать при создании набора и свойства. Исправление существующего порядка: сначала пилот (проверить, что именно меняет порядок), снимок «до» и согласование с пользователем. Ручная перестановка пользователем в панели Figma допустима.
- После любого изменения свойств открыть выпадающий список каждого свойства и проверить порядок глазами.

## Ловушки

- Скрытые слои отдают пустой children: читать с `figma.skipInvisibleInstanceChildren = false`.
- Вертикальный паддинг в коде у sm, lg и icon* не задан (высота фиксирована, `items-center`), `getComputedStyle().paddingTop` там 0. В `figma:diff` вертикальный паддинг сверяется только у md (py-2), иначе будут ложные расхождения.
- Перед массовой правкой: снимок «до» всех вариантов (геометрия, паддинги, привязки, strokesIncludedInLayout, sizing), пилот по одному варианту на пару Type × Size, затем пакеты по паре со сверкой после каждого. Любое расхождение: стоп и отчёт.

## Проверки

- `npm run figma:layout` (правило sizeConsistency: выбросы ширины, высоты и паддинга по группе Type × Size, паддинг 0, обводка при strokesIncludedInLayout=true).
- `npm run figma:diff` (Button), `npm run verify`, `tsc -b`.
- После правки пересобрать `figma/layout.json` целиком.
