# Документация компонента Inta 1.0

Для каждого компонента в `src/components/ui/` есть пара файлов: `<name>.docs.ts` и `<name>.mdx`. Образцы: button, alert, select, native-select, field. Перед работой прочитай исходник компонента, его stories и один образец рядом.

## Структура `<name>.docs.ts`

Экспорт `const <camelName>Docs: ComponentDocs` (тип из `@/docs/types`). Все тексты двуязычные `{ ru, en }` одинакового смысла.

- `title`: имя как в sidebar.
- `purpose`: 1–2 предложения.
- `whenToUse[]`: конкретные сценарии.
- `whenNotToUse[]`: `{ description, insteadOf?: { name, description } }`.
- `anatomy[]`: `{ name, description }`; имя из кода (subcomponent, слот) или понятное название части («Триггер», «Панель»).
- `variantGuidance?[]`: правила выбора между вариантами.
- `variants[]`, `states[]`: `{ name, description? }`, формат имени `prop: value`.
- `contentRules[]`, `accessibility[]`, `related[]`.
- `forDevelopers?[]`: Tailwind-классы, токены, Radix, data-slot, поведение браузера.
- `openQuestions?[]`: вопросы к человеку, на страницу не попадают, идут в отчёт PR.

## Правила текста

- Основной текст понятным языком. Классы, токены, Radix и npm-скрипты только в `forDevelopers`.
- Варианты, размеры и состояния только реальные: из `cva()` и stories. Не придумывать.
- `insteadOf` и `related` ссылаются на существующие компоненты. Если компонента нет (Toast, Link), напиши прямо «в наборе пока нет», без ссылки.
- Ссылки взаимные: если A советует B вместо себя, B упоминает A (Select и Native Select, Field и Alert).
- Доступность описывай только то, что подтверждено кодом (роль, aria, клавиатура). Если не уверен, вынеси в `openQuestions`.
- Правила контента конкретные, с примерами в кавычках («Email», а не «Введите ваш email»).
- Обращение в русском: повелительное на «вы» («используйте», «не показывайте»). Без маркетинговых оборотов, без повторов заголовка в описании.
- Русский и английский текст не расходятся по смыслу.

## `<name>.mdx`

Скопируй структуру у соседнего образца (подключение `ComponentDocsPage` и данных). Таблицы свойств (Controls/ArgTypes) на страницах пока нет, это в бэклоге: не добавляй их по своей инициативе.

## Проверки

- `tsc -b`, `npm run build-storybook`.
- Открой страницу Docs компонента в обеих локалях и в обеих темах/брендах, убедись, что все разделы рендерятся.
- Новые тексты прогони на расхождение RU/EN.
- В отчёте перечисли открытые вопросы (`openQuestions`).
