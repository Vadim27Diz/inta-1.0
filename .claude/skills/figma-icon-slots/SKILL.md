# Иконки в компонентах Figma: смена глифа из панели Properties

Применяется к дизайн-системе Inta 1.0 (Figma fileKey uUb84csG4wOfbUjB38ODiz). Перед любой записью в Figma загрузи /figma-use, создай сессию (create_session) и следуй CLAUDE.md: чужие объекты не удалять и не переписывать без вопроса, цвета только через токены.

## Правило

Если у компонента есть слот-иконка, которую пользователь может захотеть заменить, дизайнер должен менять её из панели Properties инстанса, не проваливаясь в слои.

Эталонный паттерн (как у Button):

- слот (`icon-left`, `icon-right`, `icon` и т.п.) — прямой инстанс `Icon base` (115:5) внутри компонента-варианта, с именем слоя по роли;
- на слоте `isExposedInstance = true`: в панели появляется секция по имени слоя и поле «Glyph» (свойство `glyph#115:0` типа INSTANCE_SWAP, список — глифы `li:*`);
- если иконка необязательна, её видимость привязана к BOOLEAN-свойству на корне набора (`Icon left`, `Icon right`);
- размер задаётся ресайзом самого слота и должен совпадать с кодом (Button: sm 16, md 16, lg 20, icon 16).

Плоское имя «Icon left» в панели недостижимо для вложенных инстансов: имя всегда «Glyph», слоты различаются именем слоя.

Общие `Icon` (115:32) и `Icon base` (115:5) НЕ изменять: ими пользуются все компоненты.

## Как определять иконочный слот

По структуре, а не по имени слоя: слот иконочный, если внутри есть инстанс `Icon`, `Icon base` или `li:*`. Слои с именем `media` бывают не иконками: `Card.media` — пустая рамка-заглушка, `Item.media` и `Empty.media` могут хранить другой контент. Варианты без иконки (например, `Avatar Content=initials`, `Empty Media=None`) мигрировать не нужно.

## Исключения (фиксированный глиф, swap не нужен)

Чекмарк `Checkbox` (mark), чекмарк `Select / Item`, шевроны в `Select` (триггер) и `Native Select`. `Progress → indicator` не иконка (заливка полосы). Новые исключения согласуй с пользователем и запиши в `docs/internal/decisions.md`.

`Toggle` отличается: там прямой инстанс `li:*` без `Icon base`. Не переделывай без решения пользователя (варианты: перевести на `Icon base` или привязать Instance swap прямо к глифу).

## Ограничения Figma API (проверено)

- `componentPropertyReferences` нельзя ставить на узел внутри вложенного инстанса («Cannot set component property references on instance sublayer»): привязка только к прямому потомку компонента.
- `isExposedInstance` ставится только на прямой (primary) инстанс компонента.
- Имя нового свойства не должно совпадать с существующим (иначе Figma добавит «2» и получится дубль).
- `variant.setProperties` для компонентов не подходит; дефолт свойства один на весь набор.
- Скрытые слоты (`visible=false`) отдают пустой `.children`: читать с `figma.skipInvisibleInstanceChildren = false` или временно `visible = true`, потом вернуть. `get_metadata` (XML) глубоко вложенные скрытые инстансы тоже не показывает.

## Чек-лист миграции компонента (один компонент за раз)

1. Только чтение: количество вариантов, структура слота, где используется (инвентаризация инстансов вне набора с оверрайдами глифа и заливки → `docs/internal/figma-<component>-icons-instances.json`, как у Button, либо отдельная секция внутри файла из шага 2, как у Avatar, Item, Empty, Alert; допустим любой из двух вариантов, главное — инвентаризация записана до правок).
2. Снимок «до»: слот, visible, ключ глифа (glyphKey), размер, переменная заливки вектора, привязки → `docs/internal/figma-<component>-icons-before.json`. Все glyphKey должны быть заполнены.
3. Попроси пользователя сохранить версию файла Figma (Add to version history) до массовых правок.
4. Один вариант: заменить слот на прямой инстанс `Icon base` (имя слоя восстановить: присвоение mainComponent его стирает), вернуть глиф, привязать Boolean-видимость, `isExposedInstance = true`, восстановить исходную видимость.
5. Заливка: новый глиф берёт свой дефолтный fill, а не токен слота. Починить через `setBoundVariableForPaint` по снимку.
6. Проверки на одноразовом инстансе (удалить после): смена глифа через панель или `setProperties`; цвет иконки следует за Variant и State; глиф сохраняется при переключении размера; нет «замороженных» персональных оверрайдов заливки.
7. Массовый прогон пакетами, после каждого сверка со снимком (глиф, заливка, видимость, размер, имя слоя, isExposedInstance). Сопоставлять по имени варианта и слоту, не по ID: узлы пересоздаются с новыми ID. Любое расхождение: стоп и отчёт.
8. Инвентаризация после: оверрайды в инстансах вне набора. delete+recreate слота теряет их: восстановить `setProperties({'glyph#115:0': ...})` и проверить заливку.

## Синхронизация с кодом

Структура слотов (Instance swap, Boolean) в коде ничего не меняет: иконка там обычный дочерний элемент. В код попадает только согласованность размера (например, lg 20px: `[&_svg]:size-5` в button.tsx). После кодовых изменений: `npm run verify`, `tsc -b`, `npm run build-storybook`. Chromatic покажет изменения затронутых историй: их нужно принять до мёржа.

`figma:diff` и `figma:layout` структуру слотов не проверяют (Button ими не покрыт). Правило для `figma:layout` по слотам-иконкам согласовано как план, не реализовано: экспортёр должен читать скрытые слои и сканировать минимум по одному варианту на значение структурной оси (например, Size), а не только `variants[0]`.

## Работа с пользователем

Сначала план только чтением и ожидание решения, затем правки. Итог каждого шага и принятые решения записывай в handoff (навык inta-handoff), чтобы следующий чат мог продолжить без контекста.
