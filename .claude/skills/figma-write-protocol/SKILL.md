# Протокол записи в Figma

Любая запись безопасна, только если соблюдён порядок. Нарушение порядка — не экономия времени,
а риск молча испортить набор, который постоpaет 48+ вариантов.

## Порядок, без исключений

1. **«Версия сохранена».** Жди явного подтверждения от человека (Add to version history) перед
   ЛЮБОЙ записью. Не начинай писать, пока не услышал эту фразу.
2. **Снимок «до».** Read-only через `use_figma` → `docs/internal/specs/<slug>.json` (не отдельный
   JSON-дамп на каждую мелкую правку — формат и порог размера ниже). Без снимка «до» откат после
   ошибки невозможен доказать.
3. **Пилот.** Один вариант, не весь набор. Сверь числа (геометрия, токены, привязки) с расчётом
   до того, как трогать остальные 47.
4. **Пакеты со сверкой после каждого.** Группируй по оси, которая логически связана (`Type×Size`,
   не вперемешку). Любое расхождение — стоп и отчёт, не «само пройдёт на следующем пакете».
5. **Финальная сверка.** `npm run figma:layout` (и `figma:diff`, если менялись токены/геометрия) —
   0 нарушений на ВСЕХ вариантах, не только на тех, что правили.
6. **Пересборка снимка.** Перед мёржем — `npm run figma:pull` (REST) заново, не полагаться на
   снимок с начала задачи.

## Чьи объекты можно трогать

Чужие объекты (не созданные агентом) и неизвестные страницы — не удалять, не переписывать без
вопроса, даже если мешают и выглядят как черновик. Перед любой чисткой страницы — сверить состав
и спросить про чужое.

## Скриншоты — только когда судья модель

`get_screenshot`/`node.screenshot()` в контекст агента — когда СРАВНЕНИЕ делает модель (например,
числовая проверка невозможна и нужна визуальная оценка). Когда судья — человек (а по флоу
«Figma → утверждаю» это почти всегда), агент даёт ссылку на нод/страницу, а не тянет изображение:
каждый скриншот — 1–2k токенов, за сессию их набирается десятки без пользы, если их всё равно
смотрит не модель. После пилота и после финальной правки — не повторять один и тот же скриншот,
если ничего не поменялось (см. правило 5 `/figma-use`: «самый свежий проходящий скриншот — финальный»).

## Снимки «до» — порог размера

Снимок «до» — это **таблица по различающимся наборам значений** (формат — `specs/README.md`),
не перебор всех вариантов и не полный дамп узла. Дамп крупнее **~10 КБ в контекст не идёт**:
значит нужна либо группировка (как в `figma-spec-export.js`), либо файл на диск с печатью только
сводки (счётчики, хеш) в ответ. Исторический антипаттерн, который это правило устраняет:
`figma-button-icons-before.json` на 134 КБ — перебор всех вариантов вместо таблицы по осям.

## Ловушки записи

Полный список — `references/figma-pitfalls.md` в скилле `design-tokens`. Самые дорогие по
времени на этом проекте:
- `use_figma` откатывает весь скрипт при необработанной ошибке — повторять безопасно после фикса.
- Ответ `use_figma` обрезается на ~20 КБ — гони по коллекциям/группам, не одним вызовом на всё.
- `clone()` теряет привязки текстовых свойств — восстанавливать на каждом клоне после правок.
- У скрытого экземпляра (`visible=false`) нет вложенных детей — оверрайды задавать ДО скрытия.
