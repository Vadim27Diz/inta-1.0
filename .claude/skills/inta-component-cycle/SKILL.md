# Цикл компонента: Figma → утверждаю → перенос

Пайплайн — **Figma первая, код батчами**. Эти две половины не выполняются подряд в одной
сессии: между ними — явное «переносим?» (см. `inta-port-queue`), часто другая сессия.

## Половина 1: Figma

1. **Спецификация.** Что за компонент, свойства, размеры, состояния. Источники: `shadcn/ui` как
   эталон поведения, референсные системы (логика свойств, не код). Проверь отсутствие в коде —
   `src/components/ui/`, `port-queue.md`.
2. **Component set.** Свойства 1:1 с пропсами кода (`variant`, `size`, `state`). Все
   заливки/обводки/отступы/радиусы/текст — через переменные и стили, ни одного hex. Правила
   сборки — `design-tokens/references/figma-components.md`; порядок записи — `figma-write-protocol`.
3. **«Утверждаю».** Человек смотрит Figma глазами, подтверждает. Без этого — не начинать код.
4. **Спек.** Снять **в этой же сессии** — `inta-port-queue`. Строка очереди → `queued`. Стоп —
   код не начинать сейчас, даже если «уже всё понятно».

## Половина 2: перенос (батчем, по сигналу человека)

Входные данные — только спеки из очереди, НЕ новый поход в Figma.

1. Прочитать спеки переносимых записей + **один** компонент-образец того же класса из
   `src/components/ui` (не по одному на каждый).
2. Код (shadcn + токены) по спеку — `design-tokens/references/code.md`,
   `references/shadcn-mapping.md`.
3. Истории Storybook: `Default`, `Variants`, `States`, `Content`, `BrandMatrix` (4 комбинации ×
   `surface`/`surface-raised`). `.docs.ts`/`.mdx` — `inta-component-docs`.
4. Автосверка — вся разом, одной командой: `npm run verify`
   (`tokens:check`+`tokens:contrast`+`tailwind:check`+`port:check`+`figma:diff`+`figma:layout`),
   затем `npx tsc -b`. `figma:diff` берёт ожидания из спека — не писать таблицу `EXPECT` руками
   параллельно со спеком, это тот же источник дважды.
5. Статус `ported`. Коммит в пакет (`inta-pr-package`).
6. После того как человек посмотрел Storybook — статус `verified`.
