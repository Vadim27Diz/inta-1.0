# Проект: дизайн-система ds (Figma → Storybook)

Мультибрендовая (white-label) дизайн-система со светлой и тёмной темой.
Источник правды — Figma Variables. Код — React + TypeScript + Vite, Tailwind CSS v4, shadcn/ui, Storybook.

## Перед любой задачей по UI

Загрузи скилл **design-tokens** (`.claude/skills/design-tokens/SKILL.md`) — он хаб: золотые
правила токенов и ссылки на остальные скиллы по конкретному действию (запись в Figma, перенос
компонента, очередь, пакет PR, снимок раскладки). Отдельные скиллы грузятся по своему описанию,
не нужно грузить все сразу.

## Неизменные правила

- В компонентах только семантические токены из `.claude/skills/design-tokens/references/token-catalog.md` и шкалы Tailwind. Нет hex/rgb, палитры (`bg-blue-500`), произвольных значений (`p-[13px]`), `dark:`, прозрачности вместо состояний (`bg-primary/90`).
- Пары поверхность/контент: `bg-X` + `text-on-X`.
- `src/styles/tokens.css` генерируется: правим Figma → экспорт → `npm run tokens:build`.
- Новый глобальный токен или новый бренд — только после согласования с человеком.
- Новую npm-зависимость можно ставить без согласования, но в отчёте по задаче указывать: название, лицензию, зачем нужна.
- Объекты в Figma, созданные не агентом, не удаляем и не переписываем без вопроса — даже если они мешают пересборке и выглядят как черновик. Перед любой чисткой страницы сверяем её состав и спрашиваем про чужое.
- **Figma первая, код батчами.** Компонент не переносится в код сразу после Figma: запись ждёт в `docs/internal/port-queue.md`, пока человек не скажет «переносим» (порог напоминания считает `npm run port:check`).
- **Спек снимается в той же сессии Figma**, где собирали набор, в `docs/internal/specs/<slug>.json` (формат — `docs/internal/specs/README.md`). После сжатия контекста ID узлов и числа уже не восстановить без нового похода в Figma.
- Начинать код по компоненту без строки в статусе `queued` и без файла спека — нельзя.
- `docs/internal/port-queue.md`, `decisions.md` и `handoff-archive.md` правятся только через `Edit`, никогда `Write`. Записи из очереди не удаляются никогда, отказ от переноса — строка `отложено <дата>`, а не удаление.

## Команды

| Команда | Что делает |
|---|---|
| `npm run tokens:build` | `tokens/tokens.json` → `src/styles/tokens.css` |
| `npm run tokens:catalog` | то же + обновляет каталог токенов в скилле |
| `npm run tokens:check` | линтер компонентов на «не-токены», должен давать 0 ошибок |
| `npm run tailwind:check` | каждый Tailwind-класс из `src/components` реально есть в собранном CSS, должен давать 0 ошибок |
| `npm run tokens:contrast` | WCAG и APCA для пар `X` / `on-X` во всех состояниях × 4 комбинации |
| `npm run storybook` | Storybook на :6006, тулбар Brand (main/demo) × Theme (light/dark) |
| `npm run visual` | снимки историй в 4 комбинациях бренд × тема → `visual.local/` |
| `npm run icons:stroke` | толщина линии иконок lucide-react в настоящем Chrome |
| `npm run figma:diff` | цифровая сверка Figma ↔ `getComputedStyle` в 4 комбинациях |
| `npm run figma:layout` | раскладка страницы Components по снимку `figma/layout.json` |
| `npm run port:check` | целостность очереди переноса Figma → код, должен давать 0 ошибок |
| `npm run verify` | tokens:check + tokens:contrast + tailwind:check + port:check + figma:diff + figma:layout |

## Порядок работы над компонентом

**Figma первая, код батчами**, две половины по разным сессиям — подробно в скилле
`inta-component-cycle`. Короче некуда: Figma → утверждаю → спек в этой же сессии → стоп →
(по команде человека, батчем) → код → истории → docs → `npm run verify`.

## Как работать

- **Роутинг модели.** Геометрия Figma, спорные цветовые решения — модель не переключать самому
  (эффорт/модель задаёт человек); механический перенос в код, `.docs.ts`, RU/EN-тексты — подходящая
  задача для сабагента или менее мощной модели, если доступно. Крупные Figma-аудиты и дампы —
  в сабагента, чтобы дамп не оседал в основном контексте.
- **Один компонент — одна сессия.** `/clear` между компонентами; `/context`, если ощущается
  торможение.
- Скриншоты в контекст — только когда сравнение делает модель, не человек (`figma-write-protocol`).
